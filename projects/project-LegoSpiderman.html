Lego Spider-Man

A prototype on a what-if LEGO Spider-Man game inspired by LEGO Batman: Legacy of the Dark Knight.

YouTube

Overview

A prototype on a what-if LEGO Spider-Man game inspired by LEGO Batman: Legacy of the Dark Knight. The project focuses on readable, LEGO-style gameplay with a solid AI architecture and a component-based player.

Player

Component Architecture

The player is built around a fully modular Actor Component architecture: every ability lives in its own self-contained component, meaning each system can be developed, iterated, and removed independently without touching the rest of the player.

  • Web Shooting Component
    One input action handles both a quick tap and a held input. Quick Web: three hits immobilise an enemy, and a web mesh is spawned on the enemy as visual feedback. Charged Web: a single, powerful shot with an integrated wall check. If a wall is nearby, the enemy will snap to it and be disabled. KO Launch: a physics-driven throw with a configurable parabolic arc and angular spin in flight, resulting in a clean physics shutdown on landing. Mid-flight enemy collisions are also detected, allowing chain reactions. All web interactions go through a shared interface, keeping the component fully decoupled from enemy internals.
  • Melee Component
    It handles all melee combat, including basic attacks and combos. The system is entirely self-contained, so removing the component cleanly disables all melee capability without affecting the rest of the player.
  • Web Swinging Component
    Inspired by Spider-Man 2 for the PS2, it manages all web-swinging movement — standard swings, jumping out of a swing and diving to gain speed. Without this component, the player loses the ability to swing entirely.
  • Spider Sense Component
    Triggered by an Anim Notify on an enemy's attack montage, it opens a short time window during which the player can react. If the player successfully inputs an action during this time, a slow-motion effect is triggered, combined with global time dilation, dodging and camera shake. If the window expires without input, the attack lands normally.
  • Web Hook Component
    Allows the player to quickly reposition to a target location, functioning similarly to Batman's hook in the Arkham series — a fast traversal tool rather than a combat move.
  • Stealth Takedown Component
    This ability allows the player to silently eliminate unalerted enemies, supporting both aerial and rear takedowns. The selected enemy is highlighted via a post-processing effect to provide the player with feedback. The target must be in a non-alert state.

Enemies

Enemy AI System

The AI is built on a State Tree + Behavior Tree stack driven by AIPerception (sight and damage). Enemies cycle through three states: Relaxed, Alerted, and Combat.

Combat is further subdivided into Active (currently attacking) and Passive (waiting for permission to attack), which naturally staggers the timing of attacks without the need for hardcoding delays.

Two enemy archetypes are implemented:

  • Melee — closes the distance and strikes at short range.
  • Ranged — maintains optimal distance and tracks the player with a laser. The laser fires when it centres on the player or when a timeout expires.

Token System

Inspired by combat design patterns common in action games such as the Batman: Arkham series, a token system limits how many enemies of each type can attack simultaneously. Enemies must request permission to attack and hold it for a limited number of hits before releasing it. There is a timeout safety net to prevent deadlocks and immediate revocation on web hit or stagger.

The architecture naturally supports multiple token layers, allowing fine-grained control over the combat rhythm as a whole. For instance, a two-layer configuration could distinguish between enemies that are actively attacking and those that are moving around the player. Alternatively, a three-layer configuration could introduce an intermediate layer that circulates a single token among multiple enemies in sequence, creating the impression of organised group behaviour without each enemy requiring its own token.

EQS (Environment Query System)

  • Melee EQS — generates strafing positions in a ring around the player. These positions are filtered by line of sight and the spacing between enemies to avoid clustering.
  • Ranged EQS — keeps ranged enemies at the optimal engagement distance while maintaining line of sight.

Both use a Random Best run mode to add natural variation to positioning.

Alert / Shared Cognition

When an enemy spots the player and enters Combat, it propagates awareness to all nearby enemies within a radius, forcing them into an alerted state. A debounce mechanism prevents the same alert from firing multiple times in the same frame.

PCG — City Generation

A fictional Manhattan neighbourhood

The city is procedurally generated to recreate the feel of a Manhattan neighbourhood, a dense urban grid in which streets run perpendicular to each other, dividing the space into regular city blocks. This layout is not random; it follows the same orthogonal logic as real New York boroughs, giving the world a structure that is instantly recognisable and fits the Spider-Man setting.

Modular and customisable

The entire system is built around exposed parameters — nothing is hardcoded. This includes street width, building lot dimensions, and minimum and maximum building height, among others. All values can be adjusted at any time without affecting the generation logic. This makes it easy to change the scale and density of the city, from a tight neighbourhood to a sprawling district, simply by adjusting a few numbers.

Secondary elements

Even as a prototype, the city was missing something. That's why I decided to include a set of accessory elements.

For example, cars can be found driving along the streets, or a car park occupying an entire block in place of buildings.

Animation Style

The Lego Movie aesthetic

Rather than smooth, physically realistic movement, the animations follow the stop-motion aesthetic of The Lego Movie. LEGO figures move in snappy, discrete steps — there are no flowing transitions or limb deformations, and poses are held for a moment before cutting to the next one.

This choice serves two purposes. From a technical perspective, rigid LEGO pieces cannot bend, so animating them in a stop-motion style means working with this constraint rather than against it, resulting in fewer keyframes, cleaner timing and faster iteration.

In terms of feel, the snappy rhythm reinforces the illusion that the characters are physical LEGO bricks being moved by hand — turning the game world into something that feels closer to a stop-motion set than a 3D animation.
