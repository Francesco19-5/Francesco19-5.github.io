Lego Spider-Man

A prototype on a what-if LEGO Spider-Man game inspired by LEGO Batman: Legacy of the Dark Knight.

YouTube

Overview

A prototype on a what-if LEGO Spider-Man game inspired by LEGO Batman: Legacy of the Dark Knight. The project focuses on readable, LEGO-style gameplay with a solid AI architecture and a component-based player.

Player

Component Architecture

The player is built around a fully modular Actor Component architecture: every ability lives in its own self-contained component, meaning each system can be developed, iterated, and removed independently without touching the rest of the player.

  • Web Shooting Component
    A single input action handles both a quick tap and a held input. Quick Web — three hits to immobilize an enemy, with web mesh spawned on the enemy as visual feedback. Charged Web — a single powerful shot with an integrated wall check; if a wall is nearby, the enemy snaps to it and is disabled. KO Launch — a physics-driven throw using a configurable parabolic arc, with angular spin in flight and a clean physics shutdown on landing. Mid-flight enemy collisions are also detected, allowing chain reactions. All web interactions go through a shared interface, keeping the component fully decoupled from enemy internals.
  • Melee Component
    Handles all melee combat, including standard combos and special attacks. The system is entirely self-contained — removing the component cleanly disables all melee capability without side effects on the rest of the player.
  • Web Swinging Component
    Manages all web swinging movement, including standard swings, tricks, and special swing variations inspired by Spider-Man 2. Without this component, the player loses all swinging capability entirely.
  • Spider Sense Component
    Triggered by an Anim Notify on an enemy's attack montage, it opens a short time window during which the player can react. A successful input triggers a slow motion effect — global time dilation drops while the player maintains full speed — combined with a dodge and post-process visual feedback. If the window expires without input, the attack lands normally.
  • Web Hook Component
    Allows the player to quickly reposition to a target location, functioning similarly to Batman's hook in the Arkham series — a fast traversal tool rather than a combat move.
  • Stealth Takedown Component
    Allows the player to silently eliminate unalerted enemies, supporting both aerial takedowns (from above) and rear takedowns in LEGO style. Requires the target to be in a non-alerted state.

Enemies

Enemy AI System

The AI is built on a State Tree + Behavior Tree stack driven by AIPerception (sight and damage). Enemies cycle through three states — Relaxed → Alerted → Combat — with Combat subdivided into Active (currently attacking) and Passive (waiting for permission to attack), which naturally staggers attack timing without hardcoding delays.

Two enemy archetypes are implemented:

  • Melee — closes distance and strikes at short range.
  • Ranged — maintains optimal distance and tracks the player with a laser. The laser fires when it centers on the player or when a timeout expires.

Token System

A token system (inspired by combat design patterns common in action games like the Batman Arkham series) limits how many enemies of each type can attack simultaneously. Enemies must request permission to attack, hold it for a limited number of hits, then release it — with a timeout safety net preventing deadlocks and immediate revocation on web hit or stagger.

The architecture naturally supports multiple token layers, allowing fine-grained control over the overall combat rhythm. For example, a two-layer setup could separate enemies actively attacking from those strafing around the player, while a three-layer setup could introduce a buffer layer that cycles a single token across multiple enemies in sequence — creating the illusion of coordinated group behavior without each enemy needing to hold its own slot.

EQS (Environment Query System)

  • Melee EQS — generates strafing positions in a ring around the player, filtered by line of sight and spacing between enemies to avoid clustering.
  • Ranged EQS — keeps ranged enemies at optimal engagement distance while maintaining line of sight.

Both use a Random Best run mode to add natural variation to positioning.

Alert / Shared Cognition

When an enemy spots the player and enters Combat, it propagates awareness to all nearby enemies within a radius, forcing them into an alerted state. A debounce mechanism prevents the same alert from firing multiple times in the same frame.

Animation Style

The Lego Movie aesthetic

The animations follow the stop-motion aesthetic of The Lego Movie rather than smooth, physically realistic movement. LEGO figures move in discrete, snappy steps — no flowing transitions, no limb deformation, poses held for a beat before cutting to the next.

This choice serves two purposes at once. On the technical side, rigid-body LEGO pieces don't bend, so animating them in a stop-motion style means working with the constraint rather than against it — fewer keyframes, cleaner timing, faster iteration.

On the feel side, the staccato rhythm reinforces the illusion that the characters are physical LEGO bricks being moved by hand. The game already borrows the visual language of LEGO; the animation style closes the loop — it makes the world feel like a stop-motion set, not a 3D animation.
